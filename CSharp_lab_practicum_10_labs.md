## Лабораторная работа №1. Многопоточность

**Цель:** познакомиться с потоками выполнения в C#, научиться запускать потоки и безопасно организовывать доступ к общим данным.

**Теория:**

**Процесс и поток.** Процесс — это запущенный экземпляр программы со своим виртуальным адресным пространством и системными ресурсами. Поток (`Thread`) — единица выполнения внутри процесса. У одного процесса может быть несколько потоков: каждый поток выполняет собственную последовательность инструкций, но потоки одного процесса имеют доступ к общей памяти. Благодаря этому они могут обмениваться данными, однако совместный доступ требует аккуратной организации.

**Параллелизм и конкурентное выполнение.** Конкурентность означает, что несколько задач продвигаются в течение одного периода времени: процессор может переключаться между ними. Параллелизм означает фактическое одновременное выполнение на нескольких ядрах. Несколько потоков не гарантируют ускорение: создание и переключение потоков имеют накладные расходы, а доступ к общим данным может заставлять потоки ждать.

**Создание и управление потоками.** В C# класс `Thread` находится в пространстве имён `System.Threading`. Объект потока создаётся с указанием метода, который будет выполняться. Метод `Start()` запускает поток, а `Join()` блокирует вызывающий поток до завершения указанного потока. В конструктор `Thread` можно передать метод, принимающий параметр состояния, чтобы передавать рабочему потоку необходимые данные. Поток выполняет метод до его завершения или до возникновения необработанного исключения.

**Состояние гонки и критическая секция.** Состояние гонки (`race condition`) возникает, когда результат зависит от непредсказуемого порядка выполнения потоков. Например, операция `counter++` не является одной неделимой операцией: значение нужно прочитать, увеличить и записать обратно. Если два потока выполнят эти действия одновременно, одно из увеличений может потеряться. Участок программы, работающий с общим изменяемым ресурсом, называют критической секцией.

Для защиты критической секции часто используют `lock`:

```csharp
lock (locker)
{
    counter++;
}
```

Объект `locker` служит общим маркером синхронизации. В каждый момент времени код внутри такого блока под одним и тем же объектом может выполнять только один поток. Объект блокировки обычно делают закрытым (`private`) и не используют для посторонних целей. Нельзя надолго удерживать блокировку и не следует вызывать внутри неё неизвестный внешний код — это повышает риск взаимной блокировки (deadlock).

**Другие средства синхронизации.** `Monitor` предоставляет более низкоуровневое управление блокировками; `Mutex` может синхронизировать процессы; `Semaphore` ограничивает число потоков, одновременно получающих доступ к ресурсу; `Interlocked` предоставляет атомарные операции над отдельными значениями. Выбор зависит от того, какой именно ресурс нужно защитить.

В прикладном C# часто применяют `Task` и библиотеку TPL, которые позволяют работать с задачами более высокого уровня, не управляя потоками вручную. Тем не менее понимание `Thread`, общей памяти и синхронизации необходимо для правильной разработки многопоточных программ.

**Каркас кода:**

```csharp
using System;
using System.Threading;

class Program
{
    private static int counter = 0;
    private static readonly object locker = new object();

    static void Main()
    {
        Thread firstThread = new Thread(Worker);
        Thread secondThread = new Thread(Worker);

        firstThread.Start("Поток 1");
        secondThread.Start("Поток 2");

        // Ожидаем завершения обоих потоков.
        firstThread.Join();
        secondThread.Join();

        Console.WriteLine($"Итоговое значение: {counter}");
    }

    static void Worker(object? state)
    {
        for (int i = 0; i < 5; i++)
        {
            // TODO: безопасно увеличить общий счётчик.
            lock (locker)
            {
                counter++;
            }

            Console.WriteLine($"{state}: шаг {i + 1}");
        }
    }
}
```

**Задания:**
1. Создать один поток, который выводит числа от 1 до 10, пока основной поток выводит собственные сообщения.
2. Запустить два потока: один выводит чётные числа, другой — нечётные числа в заданном диапазоне.
3. Создать несколько потоков, каждый из которых увеличивает общий счётчик. Сравнить результат с использованием `lock` и без него.
4. Реализовать поток, который вычисляет сумму элементов большого массива, пока основной поток выполняет другую работу. Передать массив потоку через параметр.
5. Написать программу с тремя рабочими потоками, которые обрабатывают разные части массива. Синхронизировать доступ к общему результату и измерить время выполнения.

## Лабораторная работа №2. Работа со строками

**Цель:** освоить основные операции обработки строк в C#, научиться искать, изменять и анализировать текст.

**Теория:**

**Строка как тип данных.** В C# строковый тип `string` (псевдоним `System.String`) представляет последовательность текстовых символов. Строки используются для хранения имён, сообщений, команд, содержимого файлов и других текстовых данных. Строковый литерал записывается в двойных кавычках, например `"Привет, C#!"`. Пустая строка `string.Empty` не содержит символов, а `null` означает отсутствие ссылки на строковый объект; это разные состояния.

**Неизменяемость строк.** Объекты `string` неизменяемы: после создания их содержимое нельзя поменять. Методы `Replace()`, `ToUpper()` и другие не редактируют исходный объект, а возвращают новую строку. Поэтому результат операции нужно сохранить:

```csharp
string original = "hello";
string upper = original.ToUpper();
// original по-прежнему содержит "hello", upper содержит "HELLO".
```

Неизменяемость упрощает совместное использование строк и предотвращает случайное изменение исходного текста. Однако многократное соединение строк в цикле может создавать много промежуточных объектов.

**Индексация и символы.** Индексы строк начинаются с нуля: `text[0]` — первый элемент строки. Свойство `Length` возвращает длину строки в единицах UTF-16, а не обязательно количество видимых пользователю символов. Некоторые символы Unicode представлены парой кодовых единиц, поэтому для полноценной обработки всех символов следует учитывать особенности Unicode и использовать `System.Text.Rune`, когда это необходимо. Для обычных учебных задач часто достаточно `char` и `foreach`.

**Основные методы обработки.** `Contains()` проверяет наличие фрагмента; `IndexOf()` возвращает позицию найденного фрагмента или `-1`; `Substring()` извлекает часть строки; `Replace()` заменяет фрагменты; `Split()` разделяет строку на части; `string.Join()` объединяет набор строк с разделителем. `Trim()` убирает пробельные символы по краям. Методы `ToUpper()` и `ToLower()` меняют регистр с учётом правил культуры; для технических идентификаторов часто применяют варианты с `StringComparison.Ordinal` или `StringComparison.OrdinalIgnoreCase`, чтобы сравнение не зависело от языка пользователя.

**Интерполяция и форматирование.** Интерполяция `$"Имя: {name}"` позволяет вставлять значения выражений прямо в строку. Форматирование помогает управлять видом чисел, дат и времени, например `$"Средний балл: {grade:F2}"` выводит число с двумя знаками после запятой.

**StringBuilder.** Класс `StringBuilder` из `System.Text` предназначен для построения текста с большим количеством изменений. Методы `Append()` и `AppendLine()` добавляют содержимое, а `ToString()` формирует итоговую строку. Его удобно использовать при накоплении результата в цикле. Для небольшого числа соединений обычный `string` и интерполяция обычно проще и понятнее.

**Каркас кода:**

```csharp
using System;
using System.Text;

class Program
{
    static void Main()
    {
        Console.Write("Введите строку: ");
        string text = Console.ReadLine() ?? string.Empty;

        Console.WriteLine($"Длина строки: {text.Length}");
        Console.WriteLine($"В верхнем регистре: {text.ToUpper()}");

        string normalized = NormalizeSpaces(text);
        Console.WriteLine($"После обработки: {normalized}");
    }

    static string NormalizeSpaces(string text)
    {
        // TODO: заменить последовательности пробелов одним пробелом.
        StringBuilder result = new StringBuilder();
        bool previousWasSpace = false;

        foreach (char symbol in text)
        {
            if (char.IsWhiteSpace(symbol))
            {
                if (!previousWasSpace)
                    result.Append(' ');
                previousWasSpace = true;
            }
            else
            {
                result.Append(symbol);
                previousWasSpace = false;
            }
        }

        return result.ToString().Trim();
    }
}
```

**Задания:**
1. Ввести строку и вывести её длину, первый и последний символы. Предусмотреть случай пустой строки.
2. Подсчитать количество гласных букв, согласных букв, цифр и пробелов в тексте.
3. Проверить, является ли введённая строка палиндромом без учёта регистра и пробелов.
4. Подсчитать количество вхождений заданного слова или подстроки в тексте. Предусмотреть выбор чувствительности к регистру.
5. Разбить текст на слова, определить самое длинное слово и сформировать новую строку, в которой слова расположены в обратном порядке.

- Для чего используются методы `Split()`, `Join()` и `IndexOf()`?

## Лабораторная работа №3. Объектно-ориентированное программирование

**Цель:** изучить основные принципы ООП в C#: инкапсуляцию, наследование, полиморфизм и абстракцию; научиться проектировать классы и взаимодействие объектов.

**Теория:**

**Классы и объекты.** Объектно-ориентированное программирование (ООП) — подход, при котором программа строится из взаимодействующих объектов. Класс описывает, какие данные и действия доступны объектам определённого типа. Объект — конкретный экземпляр класса, созданный во время выполнения с помощью `new`. Например, класс `Car` может содержать свойства `Brand` и `Speed`, а также метод `Accelerate()`.

**Поля, свойства, методы и конструкторы.** Поля хранят внутреннее состояние объекта. Свойства предоставляют управляемый доступ к данным через `get` и `set`; при необходимости в них можно проверять присваиваемые значения. Методы описывают поведение объекта. Конструктор вызывается при создании экземпляра и подготавливает его начальное состояние. Ключевое слово `this` обозначает текущий объект, а `base` используется для обращения к конструктору или членам базового класса.

**Инкапсуляция.** Инкапсуляция объединяет состояние и поведение в одном типе и защищает объект от некорректного использования. Модификаторы доступа определяют видимость членов: `public` — доступен извне; `private` — только внутри объявившего типа; `protected` — внутри типа и его наследников; `internal` — в пределах сборки. Обычно поля делают закрытыми, а взаимодействие организуют через свойства и методы. Например, баланс банковского счёта не следует разрешать произвольно менять извне: его изменяют только методы `Deposit()` и `Withdraw()`, проверяющие допустимость операции.

**Наследование.** Наследование позволяет создать производный класс на основе базового. Производный класс получает доступные ему члены базового класса и может добавлять собственные. При объявлении используется синтаксис `class Dog : Animal`. Конструктор базового класса можно вызвать через `: base(...)`. Наследование полезно, когда между типами действительно существует отношение «является разновидностью». Для простого повторного использования кода часто лучше подходит композиция — включение одного объекта в другой.

**Полиморфизм.** Полиморфизм позволяет работать с разными типами через единый базовый тип или интерфейс. Если базовый метод объявлен с `virtual` или `abstract`, производный класс может предоставить свою реализацию с `override`. При вызове виртуального метода выбирается реализация фактического типа объекта, а не только типа переменной. Поэтому список `List<Shape>` может хранить круги, прямоугольники и треугольники, а вызов `GetArea()` для каждого элемента выполнит подходящий алгоритм.

**Абстрактные классы и интерфейсы.** Абстрактный класс объявляется с `abstract`, не может быть создан напрямую и может сочетать общие поля, свойства, конструкторы и реализованные методы с абстрактными членами. Интерфейс описывает контракт, который реализующий класс обязуется предоставить. Класс может реализовать несколько интерфейсов, что позволяет задавать несколько независимых возможностей объекта. Выбор между ними зависит от задачи: общий базовый тип с состоянием и реализацией часто удобно представить абстрактным классом, а отдельную способность — интерфейсом.

**Дополнительные принципы проектирования.** Статические (`static`) члены принадлежат самому типу, а не отдельному объекту. Композиция помогает строить сложные объекты из более простых. Хорошая модель скрывает детали реализации, проверяет входные данные и предоставляет понятные операции вместо прямого доступа ко всем внутренним полям.

**Каркас кода:**

```csharp
using System;

abstract class Shape
{
    public string Name { get; }

    protected Shape(string name)
    {
        Name = name;
    }

    public abstract double GetArea();

    public virtual void PrintInfo()
    {
        Console.WriteLine($"Фигура: {Name}, площадь: {GetArea():F2}");
    }
}

class Circle : Shape
{
    public double Radius { get; }

    public Circle(double radius) : base("Круг")
    {
        if (radius <= 0)
            throw new ArgumentOutOfRangeException(nameof(radius));

        Radius = radius;
    }

    public override double GetArea() => Math.PI * Radius * Radius;
}

class Program
{
    static void Main()
    {
        List<Shape> shapes = new List<Shape>
        {
            new Circle(3)
            // TODO: добавить объекты других производных классов.
        };

        foreach (Shape shape in shapes)
            shape.PrintInfo();
    }
}
```

2. Создать класс `BankAccount` с балансом, методами пополнения и снятия средств. Запретить операции с отрицательной суммой и снятие суммы, превышающей баланс.

4. Создать абстрактный класс `Shape` и классы `Circle`, `Rectangle`, `Triangle`. Реализовать вычисление площади и продемонстрировать полиморфизм через коллекцию `List<Shape>`.

## Лабораторная работа №4. Асинхронное программирование

**Цель:** освоить асинхронную модель C#, научиться использовать `async`, `await` и `Task` для выполнения операций без блокировки вызывающего потока.

**Теория:**

**Зачем нужна асинхронность.** Некоторые операции занимают заметное время не из-за вычислений, а потому что программа ожидает внешний ресурс: чтение файла, ответ сервера, запрос к базе данных или ввод-вывод. Если выполнять такое ожидание синхронно в интерфейсном или обслуживающем потоке, приложение может перестать реагировать на действия пользователя или не сможет обслуживать другие запросы. Асинхронный подход позволяет освободить вызывающий поток на период ожидания.

**Task и Task<T>.** `Task` представляет операцию, завершение которой можно ожидать. `Task<T>` дополнительно содержит результат типа `T`. Это не то же самое, что поток: задача описывает работу или обещание получить результат, а фактическое выполнение может использовать поток, пул потоков или механизм асинхронного ввода-вывода операционной системы. Метод, который ничего не возвращает синхронно, но выполняется асинхронно, обычно объявляется как `async Task`; метод с результатом — как `async Task<T>`.

**Модификаторы async и оператор await.** Модификатор `async` разрешает использовать `await` внутри метода и позволяет компилятору преобразовать метод в механизм продолжения выполнения после ожидания. Оператор `await` приостанавливает дальнейшее выполнение этого метода до завершения ожидаемой задачи, но обычно не блокирует поток целиком. После завершения операции выполнение продолжается с места после `await`. В современных версиях C# точкой входа консольной программы может быть `static async Task Main()`.

**Пример последовательности работы:**

```csharp
static async Task<string> GetMessageAsync()
{
    await Task.Delay(1000);
    return "Готово";
}
```

Вызов `GetMessageAsync()` сразу возвращает задачу. Чтобы получить текстовый результат, вызывающий код использует `await`.

**Асинхронность и параллелизм — не одно и то же.** Асинхронность управляет ожиданием и продолжением операции; она сама по себе не означает, что вычисления выполняются параллельно. Асинхронное чтение файла может ожидать завершения системной операции, не занимая отдельный поток всё время ожидания. Для тяжёлых вычислений, которые используют процессор, можно рассматривать `Task.Run()`, но перенос CPU-нагрузки в пул потоков не делает сам алгоритм быстрее автоматически.

**Ожидание нескольких операций.** `Task.WhenAll()` создаёт задачу, завершающуюся после завершения всех переданных задач. Это удобно, когда операции независимы и их можно запустить до начала общего ожидания. `Task.WhenAny()` позволяет продолжить работу после завершения первой из нескольких задач. Последовательное ожидание независимых операций через несколько `await` может занимать больше времени, чем их совместный запуск.

**Ошибки и отмена.** Исключение из асинхронной операции сохраняется в задаче и проявляется при её ожидании через `await`. Для отмены используется кооперативный механизм `CancellationToken`: вызывающая сторона передаёт токен, а выполняющийся метод периодически проверяет запрос отмены. Создание `CancellationTokenSource` позволяет запросить отмену через `Cancel()`. Отмена не прерывает произвольный код мгновенно — метод должен поддерживать этот механизм.

**Каркас кода:**

```csharp

        Console.WriteLine($"Результат: {result}");
```

## Лабораторная работа №5. Коллекции

**Цель:** изучить обобщённые коллекции .NET и научиться выбирать структуру данных в зависимости от задачи.

**Теория:**

**Что такое коллекции.** Коллекция — объект, который хранит несколько элементов и предоставляет операции для их добавления, удаления, поиска и перебора. В отличие от массива фиксированной длины, многие коллекции могут динамически изменять размер. Большинство стандартных обобщённых коллекций находится в пространстве имён `System.Collections.Generic`.

**Обобщённые типы.** Запись `List<int>` означает список целых чисел, а `Dictionary<string, int>` — словарь, где ключом является строка, а значением — целое число. Параметр типа (`T`, `TKey`, `TValue`) задаёт тип хранимых данных на этапе компиляции. Это помогает обнаруживать ошибки типов раньше, уменьшает необходимость ручного преобразования типов и позволяет использовать одну реализацию структуры данных с разными типами.

**List<T>.** `List<T>` — динамический массив. Он предоставляет доступ к элементу по индексу через `list[i]`, свойство `Count`, а также методы `Add()`, `Remove()`, `RemoveAt()`, `Contains()`, `Sort()` и `Clear()`. Обращение по индексу обычно выполняется за постоянное время. Добавление в конец обычно эффективно, но при заполнении внутреннего массива коллекции может понадобиться выделить новый массив и скопировать элементы. Вставка или удаление в середине требует сдвига части элементов.

**Dictionary<TKey, TValue>.** Словарь хранит пары «ключ — значение» и удобен, когда элемент нужно находить по уникальному ключу: например, код товара → описание или имя → количество. Методы `Add()`, `TryGetValue()`, `ContainsKey()` и `Remove()` помогают работать со словарём. Ключи должны быть уникальными. Для безопасного чтения значения обычно удобно использовать `TryGetValue()`, чтобы не получать исключение при отсутствии ключа.

**HashSet<T>.** Множество хранит только уникальные значения. Повторное добавление уже существующего элемента не создаёт второй экземпляр этого значения. `HashSet<T>` полезен для удаления дубликатов и операций над множествами: `UnionWith()` (объединение), `IntersectWith()` (пересечение), `ExceptWith()` (разность). Корректность проверки уникальности зависит от правил сравнения и равенства элементов.

**Queue<T> и Stack<T>.** Очередь (`Queue<T>`) реализует принцип FIFO — первым извлекается элемент, который был добавлен раньше. Основные методы: `Enqueue()`, `Dequeue()` и `Peek()`. Стек (`Stack<T>`) реализует принцип LIFO — последним извлекается последний добавленный элемент; используются `Push()`, `Pop()` и `Peek()`. Очередь подходит для обработки заявок по порядку, стек — для истории действий, отмены операций и проверки вложенности.

**Перебор коллекций.** Элементы можно обрабатывать через `foreach`. Во время обычного перечисления не следует структурно изменять коллекцию (добавлять или удалять элементы): это может привести к исключению. Для изменений во время обхода можно использовать обратный цикл по индексам, отдельную копию или формировать новую коллекцию. При выборе структуры данных следует учитывать не только удобство записи, но и то, какие операции будут выполняться чаще всего.

**Каркас кода:**

## Лабораторная работа №6. Делегаты, события и лямбда-выражения

**Цель:** научиться передавать методы как значения, создавать события и использовать лямбда-выражения для компактного описания операций.

**Теория:**

**Делегаты.** Делегат — тип, который описывает сигнатуру метода: тип возвращаемого значения и типы параметров. Переменная делегата может ссылаться на любой метод, совместимый с этой сигнатурой. Благодаря этому метод можно передать в другой метод как параметр, сохранить для последующего вызова или заменить реализацию действия без изменения вызывающего кода. Делегаты являются типобезопасными: компилятор проверяет совместимость параметров и результата.

Собственный тип делегата объявляется ключевым словом `delegate`, например:

```csharp
delegate int Operation(int a, int b);
```

После этого переменной типа `Operation` можно присвоить метод, который принимает два `int` и возвращает `int`.

**Стандартные делегаты.** В повседневном C# часто не требуется объявлять собственный делегат, потому что .NET предоставляет готовые обобщённые типы:
- `Action` и `Action<T>` описывают метод без возвращаемого значения;
- `Func<T, TResult>` описывает функцию, которая возвращает результат; последний параметр типа задаёт тип результата;
- `Predicate<T>` описывает проверку элемента типа `T`, возвращающую `bool`.

Например, `Func<int, int, int>` подходит для операции над двумя целыми числами с целочисленным результатом, а `Predicate<int>` — для проверки, является ли число чётным.

**Лямбда-выражения.** Лямбда — краткая форма записи функции. Общий вид: `(параметры) => выражение` или `(параметры) => { инструкции; }`. Например, `x => x * x` описывает функцию возведения числа в квадрат. Типы параметров часто выводятся компилятором из контекста. Лямбды удобно передавать в методы сортировки, фильтрации и обработки коллекций.

**Замыкания.** Лямбда-выражение может использовать переменные из внешней области видимости. Такие захваченные переменные сохраняются для последующего использования и образуют замыкание. Нужно помнить, что лямбда может быть вызвана позже, поэтому значение захваченной переменной к этому моменту может измениться.

**События.** Событие (`event`) построено на основе делегата и реализует модель «издатель — подписчик». Издатель сообщает, что произошло событие, а подписчики выполняют свои обработчики. Подписка оформляется через `+=`, отписка — через `-=`. Ключевое слово `event` ограничивает прямое управление списком обработчиков извне класса: внешний код может подписываться и отписываться, но вызывать событие может только сам класс-владелец. Это защищает внутреннюю логику издателя.

**Вызов обработчиков и жизненный цикл подписки.** Для безопасного вызова события часто применяют условный вызов `TemperatureChanged?.Invoke(value)`: если подписчиков нет, вызова не произойдёт. Подписки следует снимать, когда они больше не нужны, особенно если издатель живёт дольше подписчика. Иначе издатель может удерживать ссылку на обработчик и мешать освобождению объекта-подписчика. Делегаты, события и лямбды часто используются вместе: событие уведомляет об изменении, а лямбда задаёт конкретную реакцию.

**Каркас кода:**

```csharp

```

## Лабораторная работа №7. Обработка исключений

**Цель:** освоить обработку ошибок и исключительных ситуаций в C#, научиться проверять входные данные и создавать собственные типы исключений.

**Теория:**

**Понятие исключения.** Исключение — объект, который сообщает об ошибочной ситуации во время выполнения программы. Примерами являются попытка деления на ноль, обращение к несуществующему файлу, преобразование некорректного текста в число или обращение к элементу массива по недопустимому индексу. В .NET исключения представлены объектами классов, производных от `System.Exception`.

**Структура обработки.** Код, в котором может произойти ошибка, помещают в блок `try`. Если возникает исключение, выполнение оставшейся части этого блока прекращается и управление передаётся подходящему блоку `catch`. Блок `finally` выполняется после `try` и соответствующего `catch` независимо от того, возникла ошибка или нет; его используют для действий, которые необходимо выполнить при завершении операции. Например, в нём можно завершить работу с ресурсом, хотя для многих ресурсов предпочтительнее конструкция `using`.

```csharp
try
{
    int number = int.Parse(input);
    Console.WriteLine(number);
}
catch (FormatException)
{
    Console.WriteLine("Введено не целое число.");
}
finally
{
    Console.WriteLine("Проверка завершена.");
}
```

**Типы исключений и порядок catch.** Разные ошибки имеют разные типы исключений: `FormatException` — неверный формат данных, `DivideByZeroException` — деление целого числа на ноль, `FileNotFoundException` — файл не найден, `UnauthorizedAccessException` — недостаточно прав доступа. Более конкретные обработчики располагают перед более общими, иначе общий обработчик может перехватить исключение раньше. Блок `catch (Exception)` не следует использовать без необходимости: он может скрыть программные ошибки, которые приложение не умеет исправлять.

**Генерация и повторное выбрасывание.** Оператор `throw` позволяет сообщить о недопустимой ситуации. Например, метод может проверить аргумент и выбросить `ArgumentOutOfRangeException`, если значение выходит за разрешённые границы. Если исключение нужно передать выше без потери исходной информации о месте возникновения, внутри `catch` используют `throw;`, а не `throw ex;`.

**Проверка данных без исключений.** Исключения предназначены для действительно исключительных ситуаций, а не для обычного управления логикой. Если ввод пользователя может быть некорректным, часто лучше использовать `int.TryParse()`: метод возвращает `true` или `false` и не выбрасывает исключение при обычной ошибке формата. Аналогично, перед делением можно проверить, что делитель не равен нулю.

**Собственные исключения.** Если предметная область содержит специальную ошибку, можно создать собственный класс, наследующий `Exception`, например `InvalidAgeException`. Имя и сообщение исключения должны ясно описывать проблему. Создавать отдельный тип стоит тогда, когда вызывающий код действительно должен различать эту ситуацию и реагировать на неё отдельно.

**Освобождение ресурсов.** Файлы, потоки и другие ресурсы операционной системы необходимо корректно закрывать. Конструкция `using` гарантирует вызов `Dispose()` при выходе из блока, в том числе при исключении. Обработка исключений должна помогать программе корректно восстановиться, показать понятное сообщение или безопасно завершить операцию, а не просто скрывать проблему.

**Каркас кода:**

```csharp

class Program
{
    static void Main()
    {
        try
        {
            Console.Write("Введите первое целое число: ");
            int first = int.Parse(Console.ReadLine() ?? string.Empty);

            Console.Write("Введите второе целое число: ");
            int second = int.Parse(Console.ReadLine() ?? string.Empty);

            int result = Divide(first, second);
            Console.WriteLine($"Результат: {result}");
        }
        catch (FormatException)
        {
            Console.WriteLine("Ошибка: необходимо ввести целое число.");
        }
        catch (DivideByZeroException ex)
        {
            Console.WriteLine($"Ошибка: {ex.Message}");
        }
        finally
        {
            Console.WriteLine("Завершение операции.");
        }
    }

    static int Divide(int a, int b)
    {
        if (b == 0)
            throw new DivideByZeroException("Деление на ноль запрещено.");

        return a / b;
    }
}
```

## Лабораторная работа №8. LINQ

**Цель:** изучить Language Integrated Query (LINQ) и научиться выполнять фильтрацию, сортировку, группировку и преобразование данных.

**Теория:**

**Назначение LINQ.** LINQ (Language Integrated Query) — встроенный в C# подход к запросам и преобразованию данных. Он позволяет описывать выборку из коллекций в декларативной форме: программист указывает, какие элементы нужны и как их преобразовать, а не пишет вручную все циклы и проверки. LINQ применяется к массивам, спискам, другим объектам, реализующим `IEnumerable<T>`, а также к некоторым внешним источникам данных через соответствующие провайдеры.

**Два способа записи запросов.** В синтаксисе запросов используются конструкции, напоминающие SQL: `from` задаёт источник, `where` фильтрует элементы, `orderby` сортирует, `select` формирует результат, `group` объединяет элементы в группы. В синтаксисе методов запрос строится цепочкой вызовов: `Where()`, `OrderBy()`, `Select()`, `GroupBy()` и т. д. Оба варианта часто представляют один и тот же смысл; синтаксис методов особенно удобен для постепенного построения цепочки и использования лямбда-выражений.

```csharp
var result = numbers
    .Where(number => number > 0)
    .OrderBy(number => number)
    .Select(number => number * number);
```

Здесь сначала выбираются положительные числа, затем сортируются, а после этого преобразуются в квадраты.

**Фильтрация и проекция.** `Where()` оставляет элементы, для которых условие возвращает `true`. `Select()` преобразует каждый элемент в значение другого типа или в новую форму данных. Например, из списка объектов `Student` можно выбрать только имена или создать анонимный объект с именем и оценкой. Такая операция называется проекцией.

**Сортировка и группировка.** `OrderBy()` сортирует по возрастанию, `OrderByDescending()` — по убыванию. Для дополнительного критерия используются `ThenBy()` и `ThenByDescending()`. `GroupBy()` объединяет элементы по общему ключу и позволяет анализировать каждую группу отдельно. Например, товары можно сгруппировать по категории, а затем посчитать количество и общую стоимость товаров в каждой категории.

**Агрегирующие операции.** `Count()` подсчитывает элементы, `Sum()` вычисляет сумму, `Average()` — среднее, `Min()` и `Max()` находят минимальное и максимальное значения. `First()` возвращает первый элемент и выбрасывает исключение, если последовательность пуста; `FirstOrDefault()` возвращает значение по умолчанию. Аналогично существуют `Single()` и `SingleOrDefault()` для сценариев, когда ожидается не более одного подходящего элемента. Выбор метода зависит от того, сколько результатов ожидается и что делать при их отсутствии.

**Отложенное и немедленное выполнение.** Многие запросы LINQ выполняются отложенно: создание переменной запроса ещё не означает, что все элементы уже обработаны. Перебор результата через `foreach` запускает выполнение запроса. `ToList()` и `ToArray()` материализуют результат — выполняют запрос и сохраняют его в новой коллекции. Методы-агрегаты вроде `Count()` и `Sum()` обычно выполняют вычисление сразу. Если источник изменился до повторного перебора отложенного запроса, результат может отличаться.

**IEnumerable<T> и производительность.** Многие операции LINQ возвращают `IEnumerable<T>`, то есть последовательность, которую можно перебрать. Цепочки операций удобно комбинировать, однако они не всегда эффективнее простого цикла. Не стоит без необходимости многократно перечислять один и тот же запрос или создавать несколько промежуточных списков. Полезно понимать, когда запрос выполняется, сколько раз он перечисляется и какой объём данных обрабатывает.

## Лабораторная работа №9. Параллельное программирование и библиотека TPL

**Цель:** познакомиться с библиотекой Task Parallel Library (TPL), научиться распараллеливать вычисления и оценивать эффективность параллельного выполнения.

**Теория:**

**Назначение TPL.** Task Parallel Library (TPL) — библиотека .NET для построения параллельных и конкурентных программ. Она предоставляет высокоуровневые инструменты, позволяющие описывать единицы работы и распределять их выполнение между доступными ресурсами системы. Основные средства TPL находятся в пространстве имён `System.Threading.Tasks`. TPL избавляет от необходимости вручную создавать и контролировать отдельный поток для каждой небольшой операции.

**Задачи Task.** Объект `Task` представляет выполняющуюся или ожидающую выполнения работу. `Task.Run()` обычно помещает CPU-нагруженную работу в пул потоков. Пул потоков повторно использует потоки, уменьшая расходы на постоянное создание и уничтожение новых. Для получения результата вычисления применяется `Task<T>`. Несколько задач можно запустить независимо и дождаться их всех с помощью `Task.WhenAll()`.

**Параллельные циклы.** `Parallel.For()` и `Parallel.ForEach()` позволяют выполнять итерации цикла параллельно. Они особенно полезны, когда обработка каждого элемента независима: например, преобразование каждого числа массива. Планировщик TPL самостоятельно распределяет работу между доступными потоками. Порядок выполнения итераций не гарантирован, поэтому нельзя полагаться на то, что сначала обработается элемент с меньшим индексом.

```csharp
Parallel.For(0, numbers.Length, i =>
{
    numbers[i] = numbers[i] * 2;
});
```

Этот пример корректен при условии, что каждая итерация изменяет отдельную ячейку массива и не затрагивает данные, которые одновременно изменяют другие итерации.

**Общие данные и потокобезопасность.** Если разные итерации меняют одну и ту же переменную, может возникнуть состояние гонки. Простое выражение `total += value` не является атомарным. Для простых числовых операций можно использовать `Interlocked`, для более сложных критических секций — `lock`, а для специальных сценариев — потокобезопасные коллекции из `System.Collections.Concurrent`. В некоторых перегрузках `Parallel.For()` можно использовать локальное состояние каждой части вычисления, а затем объединить частичные результаты; это позволяет уменьшить конкуренцию за общую переменную.

**Параллелизм и асинхронность.** TPL связана с `Task`, но параллельные вычисления и асинхронный ввод-вывод решают разные задачи. Параллелизм помогает выполнять независимую CPU-нагрузку на нескольких ядрах. Асинхронность особенно полезна при ожидании внешних операций. `Parallel.For()` предназначен прежде всего для параллельной обработки набора вычислений, тогда как `async`/`await` позволяет удобно ожидать завершения асинхронных операций.

**Измерение эффективности.** Для измерения времени удобно использовать `Stopwatch`. Сравнение должно выполняться на одинаковых данных и при одинаковых условиях. На маленьких объёмах данных затраты на распределение задач могут быть выше экономии времени. Ускорение зависит от количества доступных ядер, независимости операций, объёма синхронизации и стоимости каждой итерации. Для объективного сравнения нужно несколько раз повторить эксперимент и учитывать, что запуск приложения, прогрев JIT-компилятора и фоновые процессы могут влиять на результат.

## Лабораторная работа №10. Рефлексия

**Цель:** изучить механизм рефлексии в .NET, научиться получать сведения о типах во время выполнения и динамически создавать объекты и вызывать методы.

**Теория:**

**Понятие рефлексии.** Рефлексия (Reflection) — механизм .NET, который позволяет программе исследовать сведения о типах и их членах во время выполнения. Обычно компилятор проверяет типы и вызовы методов заранее, но с помощью рефлексии приложение может получить информацию о неизвестном заранее типе, узнать список его свойств и методов, создать объект или выполнить метод динамически. Сведения о типах хранятся в метаданных сборок .NET.

**Класс Type.** Центральный тип API рефлексии — `System.Type`. Получить описание типа можно через `typeof(Example)` на этапе компиляции или вызвать `GetType()` у уже существующего объекта. `typeof(T)` возвращает метаданные указанного типа, а `object.GetType()` сообщает фактический тип объекта во время выполнения. У объекта `Type` можно узнать `Name`, `FullName`, `Namespace`, `IsClass`, `IsInterface`, `IsAbstract` и другие характеристики.

**Исследование членов типа.** Методы `GetProperties()`, `GetFields()`, `GetMethods()` и `GetConstructors()` возвращают сведения о свойствах, полях, методах и конструкторах. Результаты представлены объектами `PropertyInfo`, `FieldInfo`, `MethodInfo` и `ConstructorInfo`. С их помощью можно узнать имя члена, тип возвращаемого значения, параметры и модификаторы доступа. По умолчанию методы получения членов возвращают определённый набор видимых членов; при необходимости применяются параметры `BindingFlags`, позволяющие выбрать, например, публичные или закрытые, статические или экземплярные члены.

**Динамическое создание объектов.** `Activator.CreateInstance()` позволяет создать экземпляр типа во время выполнения, если известен объект `Type` и доступен подходящий конструктор. Значения свойств можно получать через `PropertyInfo.GetValue()` и изменять через `PropertyInfo.SetValue()`. Для этого нужно учитывать тип значения, наличие `get` или `set`, доступность свойства и возможность преобразования передаваемых данных.

**Динамический вызов методов.** Метод `MethodInfo.Invoke()` вызывает найденный метод. В него передаётся целевой объект (для статического метода — `null`) и массив аргументов. Число и типы аргументов должны соответствовать сигнатуре метода. Ошибки поиска или вызова нужно обрабатывать: метод может отсутствовать, быть недоступным, получить неподходящие аргументы или выбросить исключение во время выполнения. Исключение из вызываемого метода при рефлексивном вызове обычно оборачивается в `TargetInvocationException`; исходную причину можно исследовать через `InnerException`.

**Атрибуты и метаданные.** Атрибуты позволяют прикреплять к классам, методам, свойствам и другим элементам дополнительную информацию. Например, собственный атрибут `[Description("...")]` может хранить описание класса. Атрибут объявляется как класс, производный от `Attribute`, а его наличие и значения можно прочитать с помощью `GetCustomAttribute<T>()` или `GetCustomAttributes()`.

**Сборки и сценарии применения.** Через `Assembly` можно исследовать типы, входящие в сборку, например получать список типов и анализировать их. Рефлексия используется в механизмах сериализации, системах плагинов, ORM, тестовых фреймворках, инструментах диагностики и редакторах. Она даёт гибкость, но обычно сложнее обычного статического вызова и может иметь дополнительные затраты времени выполнения. Код, использующий рефлексию, нужно проектировать осторожно: ошибки обнаруживаются позже, а доступ к закрытым членам или динамическая загрузка неизвестных сборок могут создавать риски безопасности. Для простых заранее известных операций предпочтительнее обычные типизированные вызовы.
